# Цементная мельница — настольное приложение PySide6

Оконная исследовательская модель **одного барабана с одной или двумя камерами**. Интерфейс полностью на **PySide6 (Qt 6)**, без Tkinter, Streamlit или браузера. Математическое ядро и экспорт Excel остались самостоятельными Python-модулями.

> Результаты без калибровки являются демонстрационным прогнозом, а не подтверждёнными замерами цементного завода.

## Запуск на Fedora и в PyCharm

```bash
cd ~/Downloads/melnitsa-proj
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

В PyCharm выберите `.venv/bin/python` в качестве интерпретатора и запускайте **`main.py`** кнопкой Run. Если ранее использовалось существующее `.venv`, достаточно обновить зависимости: `.venv/bin/python -m pip install -r requirements.txt`. Отдельно устанавливать `python3-tkinter` не требуется.

При проблемах с Qt в Fedora проверьте системные зависимости графической среды и наличие пакетов `xcb`; запускать приложение нужно в графическом сеансе. Для ручного запуска Qt-тестов без экрана можно использовать `QT_QPA_PLATFORM=offscreen`.

## Возможности

- **Барабан и камеры.** Один барабан, 1–2 камеры; независимые внутренние диаметры и длины, обороты, измеренная мощность. Общая длина рассчитывается автоматически, физический диаметр камеры не меняется от износа мелющих тел.
- **Грансостав клинкера.** Десять фракций вводятся вручную, ползунками, из CSV или демонстрационного пресета HTML; проверяется сумма около 100 %. F80 рассчитывается из фракций входа, P80 — из модельного выхода. Лабораторные параметры не редактируются оператором.
- **Подача и мельница.** Измеренная подача либо выпуск/время, интервалы Q(t), геометрия и режим камер, масса и состав мелющих тел.
- **Износ.** Прогноз по времени, остаточная масса, текущий диаметр мелющих тел, удельный износ по фракциям и рекомендации догрузки.
- **Сита.** Стандартные и пользовательские размеры, выбор для диаграммы помола и таблицы проб; контроль R0,08 и R0,045 считается независимо от выбора сит.
- **Мелющие тела / догрузки.** Редактирование строк в таблицах Qt. Новая догрузка создаётся сразу со стандартными значениями, без всплывающего окна. Фракции могут отличаться по форме, материалу, диаметру и массе.
- **Обзор.** Шесть диаграмм, включая производительность Q(t), накопленный выпуск, общий износ и средние диаметры мелющих тел по камерам. Масштабирование графиков через панель Matplotlib.
- **Симуляция смен.** Отдельная вкладка: выбор вида цемента, дней и часов работы в день, расчётных R0,08, R0,045 и Блейна с целевыми границами. Показываются исходный прогноз и сценарий коррекции загрузки.
- **Excel.** Экспорт в меню **Файл** формирует таблицы, исходную загрузку, нормативные границы и сравнительные диаграммы `.xlsx` через `XlsxWriter`.

Поля автоматически пересчитываются после изменения корректного значения; отрисовывается только открытая вкладка. Тяжёлая симуляция смен выполняется в рабочем потоке, чтобы не блокировать управление. При ошибочных данных показывается сообщение об ошибке.

## Порядок работы сотрудника

1. Откройте слева **«Грансостав клинкера»** и введите десять массовых долей вручную или импортируйте CSV через **Файл**. Сумма должна быть около 100 %.
2. На вкладках **«Барабан и камеры»**, **«Подача и клинкер»** и **«Мелющие тела»** введите фактическую геометрию, частоту вращения, мощность, производительность, начальную загрузку по фракциям и камерам.
3. Откройте справа **«Симуляция смен»**. Выберите одну из пяти технологических карт цемента (взяты из `references/1233223_fixed_norm.html`), количество дней и часов работы в день, минимальную производительность.
4. Нажмите **«Пуск»**. На трёх графиках отображаются R0,08, R0,045 и расчётный Блейн по рабочим часам, допустимые границы, первое отклонение, исходный прогноз и прогноз после предлагаемой коррекции.
5. Проверьте найденное предложение догрузки или выгрузки. **Догрузку** можно перенести в модельный журнал после подтверждения; **выгрузка** остаётся рекомендацией для технолога и не записывается как отрицательная догрузка. Экспортируйте отчёт через **Файл → Экспорт отчёта Excel**.

## Источник целевых карт и ограничения прогноза

Пять карт R0,08/R0,045/Блейна восстановлены из сохранённой HTML-версии. **Это технологические цели симуляции, не полный перечень обязательных требований ГОСТ 31108-2020.** Подробности: `doc/research/03-html-standards.md`.

Индекс Блейна здесь — **эмпирический прокси**, а не результат лабораторного прибора. Износ и тонкость помола требуют калибровки на производственных пробах. Подбор оптимизирует продолжительность соответствия на дискретной временной сетке среди **одиночных операций над одной фракцией** (догрузка или выгрузка приблизительно 5–35 %), учитывая предварительное заполнение камеры. Оптимум не гарантируется ни по непрерывному времени, ни среди всех возможных комбинаций.

**Особо важно:** `Q(t)` задано оператором и не пересчитывается вследствие изменения загрузки. Программа может проверить только заданный минимум производительности, но не доказать сохранение фактической производительности после догрузки. Решение для цеха требует проверки технологом, паспортов мельницы и лабораторных измерений. План развития: `doc/plan/05-production-controls.md`, `doc/plan/06-shift-simulation.md`.

## Графики и целое количество мелющих тел

- На временных графиках есть поле «Час работы», ползунок, вертикальная линия выбранного часа и показания рядов. Ползунок не изменяет расчётную модель.
- Панели Matplotlib скрыты; легенды вынесены за пределы данных. Высоту симуляции увеличили, вкладка прокручивается.
- Количество шаров и цильпебсов **строго целое** (округление половин вверх при переводе заданной массы в число тел). После округления действительная масса вычисляется из количества и диаметра; износ изменяет размер/массу, но не дробит штуки. Выгрузка распределяет целые штуки по партиям.
- Справка по переменным открывается в обычном диалоге Qt без системного звука.

Локально проверьте: `python -m pytest -q tests/test_integer_media.py tests/test_plot_time_controls.py tests/test_shift_simulation.py`. Автоматические GitHub Actions-тесты отключены.

## Смена цемента и параметров по часам

- Левая и правая панели скрываются отдельными кнопками; оставшаяся растягивается. Поля настройки износа перенесены в правую вкладку «Прогноз износа». Кликабельные подписи жёлтые; есть пояснение L/D цильпебса.
- Вкладка **«Симуляция работы»** отображает R0,08, R0,045, расчётный Блейн и массу мелющих тел с изменяющимися границами цемента.
- На вкладке **«Журнал изменений»** оператор указывает рабочий день и час, затем смену цемента, догрузку/выгрузку по фракции либо изменение режима (обороты, мощность, диаметр, выпуск, циркуляционная нагрузка, запас, влажность, температура).
- Вкладка **«История изменений»** показывает массы фракций, марки цемента и параметры. Таблицы содержат час наработки, день/час и значения «было/стало». Перерасчёт продолжается от состояния на момент события.
- События сохраняются с конфигурацией JSON; Excel дополняется листами `Изменения_цемента`, `Изменения_тел`, `Изменения_параметров`.

**Ограничения:** смена марки меняет технологическую карту, но не мгновенную физическую тонкость помола. Изменение диаметра барабана означает сценарий реконструкции, а не эксплуатационную настройку. Модель Q остаётся внешней и не доказывает сохранение производительности после догрузки. Блейн и износ требуют калибровки по заводу. Поиск операции дискретен, а не глобально оптимален.

## Многопроцессный расчёт и рабочее место оператора — 13.11.2026

**Запуск Windows/PyCharm:** `py -3.11 main.py`. В `main.py` используется `multiprocessing.freeze_support()` и импорт Qt защищён `if __name__ == '__main__'`. Для запуска через PyCharm выберите интерпретатор с PySide6 и Matplotlib.

- **Многопроцессный подбор (фазы 08–09):** программа проверяет ограниченные комбинации из 1–3 одновременных догрузок/выгрузок целых мелющих тел. Независимые сценарии рассчитываются с `ProcessPoolExecutor(spawn)`, максимум 8 процессов; при отказе пула предусмотрен последовательный режим. Перед вмешательством состояние сохраняется, повторно рассчитывается только оставшийся период. На Windows убедитесь в реальной загрузке нескольких ядер и измерьте wall-clock.
- **Отрисовка:** `multicore_render.py` создаёт PNG из Matplotlib Agg в отдельных процессах, но виджеты PySide6 изменяет только основной GUI-поток. Невидимые вкладки отрисовываются при открытии. Графики времени используют единый результат хронологии.
- **Исходные данные:** четыре бывших левых раздела сведены в прокручиваемую форму со сворачиваемыми группами (грансостав, барабан, подача, сита, параметры износа). Отдельно остаются мелющие тела и догрузки/выгрузки.
- **Симуляция работы:** шесть графиков выбираются из списка: R0,08, R0,045, расчётный Блейн, масса загрузки, накопленный износ, средние диаметры тел.
- **Журнал и история:** только для чтения, формируются из расписания событий и подтверждённых вмешательств. Планировать будущие изменения можно в симуляции, а рекомендованную догрузку подтвердить в разделе рекомендаций; догрузки попадают в `manual_reloads`, выгрузки в `media_events`.
- **Рекомендации:** показывают все операции выбранного сценария либо диагностику причин отсутствия подходящей комбинации (в том числе нарушение Q, которое модель физически не исправляет догрузкой). «Заводская история» временно скрыта в интерфейсе; код калибровки оставлен.

**Ограничения:** выбор оптимален только среди исследованных комбинаций на дискретной сетке. Производительность Q задаётся извне и не может считаться физически рассчитанной реакцией на догрузку. Блейн — прокси, а не лабораторное измерение. Для заводских рекомендаций необходимы калибровка и согласование с технологом.

## Группировка результатов и адаптивные графики (14.11.2026)

Обновлены правые разделы:
- **Контроль помола**: этап 1 — диаграмма по длине камер; этап 2 — таблица проб с равномерными числовыми колонками и горизонтальной прокруткой. Значение R0,045 не меняется: исправлена растянутая последняя колонка.
- **Мелющие тела**: этап 1 — начальная загрузка; этап 2 — износ фракций. Для износа выбирается один крупный график: диаметр, масса либо удельный износ. Сохраняется выбор камеры.
- Раньше в интерфейсе были фиксированные или слишком большие минимальные размеры вложенных форм. В узкой левой колонке подписи переносятся над полями, при расширении форма перестраивается без потери введённых значений.

**Все диаграммы адаптируются к размерам окна:** Matplotlib QtAgg («Обзор», «Диаграмма помола», «Начальная загрузка») изменяет свой холст и перерисовывает его без пересчёта модели. PNG графики симуляции, журнала, износа и прогноза готовятся через Agg в фоновых процессах в размере, соответствующем текущему видимому блоку, с разрешением 2×. Масштабирование PNG выполняется с сохранением пропорций, в том числе для линии выбранного часа. Рендеринг при перемещении разделителя имеет задержку 360 мс; скрытые графики не запускаются.

Модули должны подключаться в следующем порядке: `staged_results_ui`, `responsive_ui`, `adaptive_graphs_ui` — после остальных расширений `MillWindow`. Существующие данные и формулы мельницы не менялись. Код работает поверх основной ветки без ручной установки старых ZIP.
