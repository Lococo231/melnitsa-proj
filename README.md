# Цементная мельница — настольное приложение PySide6

Оконная исследовательская модель **одного барабана с одной или двумя камерами**. Интерфейс полностью на **PySide6 (Qt 6)**, без Tkinter, Streamlit или браузера. Математическое ядро и экспорт Excel остались самостоятельными Python-модулями.

> Результаты без калибровки являются демонстрационным прогнозом, а не подтверждёнными замерами цементного завода.

## Запуск на Fedora и в PyCharm

```bash
cd ~/Downloads/melnitsa-proj
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

В PyCharm выберите `.venv/bin/python` в качестве интерпретатора и запускайте **`main.py`** кнопкой Run. Если ранее использовалось существующее `.venv`, достаточно обновить зависимости: `.venv/bin/python -m pip install -r requirements.txt`. Отдельно устанавливать `python3-tkinter` не требуется.

При проблемах с Qt в Fedora проверьте системные зависимости графической среды и наличие пакетов `xcb`; запускать приложение нужно в графическом сеансе. Для ручного запуска Qt-тестов без экрана можно использовать `QT_QPA_PLATFORM=offscreen`.

## Возможности

- **Барабан и камеры.** Один барабан, 1–2 камеры; независимые внутренние диаметры и длины, обороты, измеренная мощность. Общая длина рассчитывается автоматически, физический диаметр камеры не меняется от износа мелющих тел.
- **Грансостав клинкера.** Десять фракций вводятся вручную, ползунками, из CSV или демонстрационного пресета HTML; проверяется сумма около 100 %. F80 рассчитывается из фракций входа, P80 — из модельного выхода. Лабораторные параметры не редактируются оператором.
- **Подача и мельница.** Измеренная подача либо выпуск/время, интервалы Q(t), геометрия и режим камер, масса и состав мелющих тел.
- **Износ.** Прогноз по времени, остаточная масса, текущий диаметр мелющих тел, удельный износ по фракциям и рекомендации догрузки.
- **Сита.** Стандартные и пользовательские размеры, выбор для диаграммы помола и таблицы проб; контроль R0,08 и R0,045 считается независимо от выбора сит.
- **Мелющие тела / догрузки.** Редактирование строк в таблицах Qt. Новая догрузка создаётся сразу со стандартными значениями, без всплывающего окна. Фракции могут отличаться по форме, материалу, диаметру и массе.
- **Обзор.** Шесть диаграмм, включая производительность Q(t), накопленный выпуск, общий износ и средние диаметры мелющих тел по камерам. Масштабирование графиков через панель Matplotlib.
- **Симуляция смен.** Отдельная вкладка: выбор вида цемента, дней и часов работы в день, расчётных R0,08, R0,045 и Блейна с целевыми границами. Показываются исходный прогноз и сценарий коррекции загрузки.
- **Excel.** Экспорт в меню **Файл** формирует таблицы, исходную загрузку, нормативные границы и сравнительные диаграммы `.xlsx` через `XlsxWriter`.

Поля автоматически пересчитываются после изменения корректного значения; отрисовывается только открытая вкладка. Тяжёлая симуляция смен выполняется в рабочем потоке, чтобы не блокировать управление. При ошибочных данных показывается сообщение об ошибке.

## Локальная проверка (без GitHub Actions)

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
```

**Автоматические тесты при отправке изменений в GitHub отключены.** Каталог `tests/`, `pytest.ini` и `requirements-dev.txt` сохранены для ручных проверок. Workflow `.github/workflows/tests.yml` удалён.

Импортируйте конфигурацию из `examples/` через меню **Файл → Импорт параметров JSON**. Файлы `model.py` и `blackbox_cli.py` сохранены для машинного вызова Black Box без интерфейса.

**Физические ограничения:** лабораторный индекс Бонда определяется до помола по протоколу; без испытания значение не подменяется расчётом из размера барабана. Производительность сама по себе не становится переменной от износа: для этого нужен измеренный график Q(t) или калиброванная зависимость.

## Порядок работы сотрудника

1. Откройте слева **«Грансостав клинкера»** и введите десять массовых долей вручную или импортируйте CSV через **Файл**. Сумма должна быть около 100 %.
2. На вкладках **«Барабан и камеры»**, **«Подача и клинкер»** и **«Мелющие тела»** введите фактическую геометрию, частоту вращения, мощность, производительность, начальную загрузку по фракциям и камерам.
3. Откройте справа **«Симуляция смен»**. Выберите одну из пяти технологических карт цемента (взяты из `references/1233223_fixed_norm.html`), количество дней и часов работы в день, минимальную производительность.
4. Нажмите **«Пуск»**. На трёх графиках отображаются R0,08, R0,045 и расчётный Блейн по рабочим часам, допустимые границы, первое отклонение, исходный прогноз и прогноз после предлагаемой коррекции.
5. Проверьте найденное предложение догрузки или выгрузки. **Догрузку** можно перенести в модельный журнал после подтверждения; **выгрузка** остаётся рекомендацией для технолога и не записывается как отрицательная догрузка. Экспортируйте отчёт через **Файл → Экспорт отчёта Excel**.

## Источник целевых карт и ограничения прогноза

Пять карт R0,08/R0,045/Блейна восстановлены из сохранённой HTML-версии. **Это технологические цели симуляции, не полный перечень обязательных требований ГОСТ 31108-2020.** Подробности: `doc/research/03-html-standards.md`.

Индекс Блейна здесь — **эмпирический прокси**, а не результат лабораторного прибора. Износ и тонкость помола требуют калибровки на производственных пробах. Подбор оптимизирует продолжительность соответствия на дискретной временной сетке среди **одиночных операций над одной фракцией** (догрузка или выгрузка приблизительно 5–35 %), учитывая предварительное заполнение камеры. Оптимум не гарантируется ни по непрерывному времени, ни среди всех возможных комбинаций.

**Особо важно:** `Q(t)` задано оператором и не пересчитывается вследствие изменения загрузки. Программа может проверить только заданный минимум производительности, но не доказать сохранение фактической производительности после догрузки. Решение для цеха требует проверки технологом, паспортов мельницы и лабораторных измерений. План развития: `doc/plan/05-production-controls.md`, `doc/plan/06-shift-simulation.md`.

### Новые листы Excel

Дополнительно создаются: `Пробы_по_длине`, `Начальная_загрузка`, `Нормы_и_выпуск`, `План_догрузки_к_концу`, `Симуляция_смен`, `Коррекция_загрузки`, `Границы_цемента`. Старые листы отчёта сохраняются. История изменений — `CHANGELOG.production.md`.

**Совместимость старых JSON:** если календарь смен в конфигурации не указан, прежние листы Excel экспортируются полностью, а три листа сменного сценария содержат пометку «Не рассчитано». Симуляция не придумывает часы и дни и не обрезает сохранённый график Q(t).

### Windows / PyCharm — меню приложения

После обновления в PyCharm запустите `main.py` обычным способом. Меню «Файл» и «Модель» теперь закреплены за главным окном и не должны исчезать во время построения интерфейса. Это исправляет причину ошибки `RuntimeError: Internal C++ object (PySide6.QtWidgets.QMenu) already deleted`, обнаруженной при запуске на Windows. Проверка в реальной Windows-среде ещё нужна; статус отражён в `doc/todo.md`.
