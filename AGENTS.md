# AGENTS.md — агентские правила проекта melnitsa-proj

## Назначение и статус
Настольный исследовательский симулятор цементной шаровой мельницы. Текущая реализация моделирует **один барабан с одной или двумя камерами** (не четыре мельницы одновременно). Отображает эволюцию состава мелющей загрузки, износ, догрузки, условную тонкость помола, ситовые остатки, производительность Q(t), выпускает Excel-отчёт. Прогноз без калибровки НЕ является заводским измерением или достоверной рекомендацией для оборудования.

## Стек и структура
- Python 3.11/3.13; PySide6 (Qt 6) — настольный UI; Matplotlib + QtAgg — графики; XlsxWriter — Excel; pytest — локальное тестирование без автоматического GitHub Actions.
- `main.py` — основной entrypoint; `project/app.py` — альтернативный запуск.
- `project/qt_app.py` — UI и интеграция; `project/ui_data.py` — преобразование/валидация UI; `project/model.py` — единственный источник математических расчётов.
- `project/calibration.py` — обработка истории CSV; `project/excel_export.py` — экспорт; `project/blackbox_cli.py` — расчёт JSON без UI.
- `examples/` — входные демонстрационные сценарии; `tests/` — локальные проверки. Автоматический тестовый workflow GitHub Actions удалён по просьбе пользователя.
- `docs/MODEL_AND_DOMAIN.md` — ранее описанные формулы/условности; `doc/research/` — выписки из исследований; `doc/plan/` — фазы; `doc/todo.md` — оперативный steering.

## Непереговорные ограничения
1. Сохранять разделение UI, модели и экспорта. `model.py` не импортирует Qt. Изменения расчётов сопровождаются численными тестами.
2. Один барабан, 1–2 камеры; `L_барабана = Σ L_камер + перегородка`. Внутренние диаметры камер — паспортная геометрия и НЕ уменьшаются при износе мелющих тел.
3. Диаметры шаров/цильпебсов, их масса, форма (`L/D` для цильпебса), материал и камера задаются явно. Не смешивать массу отдельных фракций и массу загрузки камеры.
4. `Q(t)` задаётся фактической подачей или расписанием; не выводить его изменение из износа без эмпирической идентификации. Единицы: т/ч, часы, тонны, мм, кВт, мкм, кВт·ч/т; проверять конверсии.
5. Лабораторный Bond Wi только из отдельного протокола, эксплуатационный Wi из P/Q и F80/P80, не смешивать. F80/P80 из распределений, а не из диаметра камеры.
6. Параметры `wear_g_t`, скорости помола и Blaine proxy — калибруемые допущения. Приводить видимые предостережения об отсутствии калибровки.
7. Догрузка — новая партия с отдельным временем, размером, материалом и формой. Изменения корректного ввода обновляют расчёт; некорректный ввод не должен выдавать старый график за свежий.
8. Проверять сохранение массы с учётом истирания, выбраковки и догрузок, монотонность накопленного выпуска и корректное поведение на нулевом горизонте.
9. Не ломать JSON/CSV-форматы `examples/`, CLI и экспорт. При несовместимости — явная миграция и тест.
10. Без секретов и заводских конфиденциальных исходников в публичном репозитории. Не редактировать автогенерированные файлы и виртуальное окружение.
11. Не коммитить и не пушить без прямой команды пользователя. `AGENTS.local.md` должен оставаться только локально и в `.gitignore`.
12. Документировать текущую реализованную функциональность отдельно от требований и будущих фаз: не утверждать, что план уже выполнен.

## Процесс агента
Перед задачей прочесть `AGENTS.md`, при наличии локального файла `AGENTS.local.md`, актуальные `doc/todo.md`, соответствующий план и исследования. Реализовать минимальный законченный срез, прогнать затронутые тесты, обновить исследования/планы при новых подтверждённых фактах. В `doc/todo.md` добавлять задания от пользователя; после реального выполнения и проверки **удалять** соответствующий пункт, не отмечать выполненное как активное. Планы — постоянный исторический ориентир. Без команды пользователя не создавать коммиты, PR и теги.

## Рабочий сценарий и изменения фазы 05–06 (08.11.2026)
- Оператор вводит десять фракций грансостава клинкера вручную, слайдерами или CSV, затем паспортные и измеренные параметры барабана/камер, Q(t) и исходную мелющую загрузку. Не создавать ручные регуляторы лабораторных свойств клинкера, которые невозможно задать на производстве.
- Вкладка «Симуляция смен»: вид цемента, дни, часы работы в день; остановки между сменами не создают дополнительного износа. R0,08, R0,045 и Блейн выводить как расчётные траектории с границами и отметками нарушений. При изменениях обновлять только активную диаграмму; остальные строить при открытии.
- Референс карт: `references/1233223_fixed_norm.html`; выписка ограничений — `doc/research/03-html-standards.md`. Эти цели из HTML НЕ являются обязательными нормативами ГОСТ; Blaine в модели — proxy, не физическое измерение.
- `project/production_ui.py` добавляет производственные элементы и ленивую отрисовку; `project/workflow_ui.py` добавляет сценарий смен; `project/production_planning.py` содержит профили и оценку догрузки; `project/shift_simulation.py` — интеграцию износа и дискретный подбор; `project/production_export.py`, `project/shift_export.py` расширяют Excel. Интеграция выполняется из `qt_app.py` и `excel_export.py`.
- При подборе сравнивать исходную траекторию с результатом операции при том же входе, учитывать оба направления (догрузка/выгрузка), заполнение камеры, все заданные диапазоны качества и нижний порог Q. Не выдавать найденный по одной фракции локальный план за доказанный глобальный оптимум. Выгрузку не кодировать как отрицательную догрузку.
- На каждый запрос вести накопительное описание исполненных изменений в `CHANGELOG.production.md` и обновлять `doc/plan/`, `doc/research/`, `doc/todo.md`; не коммитить `AGENTS.local.md`, `*.bak`, локальные бэкапы и заводские конфиденциальные данные. Коммиты — только по прямой команде пользователя.
- Проверки: `tests/test_production_update.py`, `tests/test_shift_simulation.py`, все старые модельные/Qt/экспортные тесты, проверка UI в `QT_QPA_PLATFORM=offscreen`. Полная проверка на установленном PySide6 и калибровка по цеховым данным остаются открытыми задачами.

## Правила хронологии (фаза 07)

- `project/operation_timeline.py` содержит ядро событий без Qt; `project/timeline_ui.py` — PySide6-расширение, подключаемое после `production_ui` и `workflow_ui`.
- Время событий — часы суммарной наработки с отображением рабочего дня/часа. Смена марки цемента меняет технологическую карту, а не химический состав или состояние загрузки.
- Число мелющих тел целое; масса определяется через количество и текущий диаметр, износ уменьшает массу и диаметр без дробления штук.
- Изменение паспортного диаметра барабана допустимо только как сценарий реконструкции, не регулятор действующей мельницы.
- Не восстанавливать GitHub Actions. Коммиты — только по команде; `AGENTS.local.md` не отправлять.

## Фазы 08–10: вычисления и интерфейс оператора (13.11.2026)

- `project/operation_timeline.py` — расчёт единой хронологии и ограниченный поиск комбинированных операций, независимый от Qt; `multicore_ui.py` — мост Qt к рабочему пулу, `multicore_render.py` — PNG через Agg, `workspace_logic.py` — общий временной ряд, анализ причин и журнал, `workspace_ui.py` — перестройка видимых страниц поверх существующих виджетов.
- Порядок установки расширений класса `MillWindow`: `production_ui` → `workflow_ui` → `timeline_ui` → `multicore_ui` → `workspace_ui`. Не менять порядок без регрессионной проверки.
- Один горизонт `simulation_days × simulation_hours_per_day` для всех временных графиков. Источник — результат динамической хронологии, не старый `simulate_wear` при наличии вмешательств. Журнал только для чтения.
- Все кандидаты догрузки/выгрузки используют целое количество штук и проверяют заполнение камер. Если Q вне заданного диапазона, не выдавать физически бесполезное изменение мелющих тел за его исправление.
- В Windows `spawn` с `freeze_support`; код в процессах не импортирует Qt и не создаёт QWidget; UI обновляется в главном потоке. Ленивая PNG-отрисовка для скрытых вкладок.
- Границы модели: калибровка износа/помола/Блейна, связь массы загрузки с Q, ограниченность сетки и набора кандидатов; не заявлять глобальный оптимум или соответствие ГОСТ.
- Проверки локальными тестами `tests/test_multicore_*.py`, `tests/test_parallel_timeline.py`, `tests/test_formula_invariants.py`, `tests/test_workspace_*.py`; GitHub Actions не возвращать. `AGENTS.local.md` не коммитить.

## Фазы 11–13 — компоновка Qt и разрешение всех диаграмм

- Подключать после `workspace_ui.install`: сначала `staged_results_ui.install`, затем `responsive_ui.install`, последним `adaptive_graphs_ui.install`.
- Новые правые группы: «Контроль помола» (диаграмма/пробы), «Мелющие тела» (начальная загрузка/износ); сохраняются старые объекты PlotPanel/QTableWidget и индексы совместимости, прежние вкладки 4/7 скрываются.
- `QSplitter`, `QScrollArea` и `QFormLayout` должны изменять ширину содержимого. При узком окне включать `QFormLayout.WrapAllRows`, не добавлять фиксированные минимальные ширины панелей. Таблицы допускают внутреннюю горизонтальную прокрутку.
- Для всех групп Matplotlib Agg (`sim*`, `history*`, `fraction_*`, `forecast*`) передавать `target_size`, рендерить 2× от логического размера видимого изображения. `HourPlotImage` сохраняет пропорции изображения и координату курсора; не использовать `setScaledContents(True)`.
- Не перезапускать тяжёлую модель при изменении ширины окна. Дебаунс 360 мс, один активный запрос на группу и проверка поколения симуляции. Qt/виджеты строго в главном потоке; Agg в фоновых процессах.
- Нативный Matplotlib QtAgg корректно меняет размеры сам, `canvas.draw_idle()` выполняется в GUI потоке, когда график виден. DPI и переразмеривание проверить на Windows, также в 4K.
- Сохранять накопительный `CHANGELOG.production.md` и `doc/todo.md`. Запрещено коммитить `AGENTS.local.md`, `*.bak`; GitHub Actions остаётся отключён. Тесты запускаются локально.
