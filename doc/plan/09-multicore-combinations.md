# Фаза 09 — многопроцессный подбор и графики (10.11.2026)

## Реализовано в пакете

- Раздельные Python-процессы `spawn` для каждого независимого кандидата. Один пул используется на этапах одиночных, парных и тройных операций. Не более 8 процессов; при сбое запуска предусмотрена последовательная резервная схема.
- Состояние мельницы до вмешательства не пересчитывается для каждого кандидата. Проверяются целые штуки, фактическое заполнение, действующие на соответствующий час показатели R0,08/R0,045/Блейна и минимум Q.
- Комбинации выбираются **в один час**, максимум три операции над **различными фракциями**. Применён ограниченный beam-search с ранним завершением при выходе из нормы. Результат не является математическим глобальным оптимумом.
- Четыре графика симуляции готовятся в дочерних процессах Matplotlib Agg; результаты — PNG. Графики истории, фракций и прогноза создаются **только при открытии** соответствующей вкладки. QWidget создаются/обновляются исключительно в GUI-потоке Qt; линия выбранного часа — Qt/QPainter.
- Полный план может быть перенесён в журнал как несколько связанных по часу событий, включая выгрузку. Отчёт Excel должен учитывать те же события после подтверждения плана.

## Оставшиеся проверки

- End-to-end запуск на Windows с реальным PySide6, корректность завершения процессов при закрытии окна.
- Профилирование CPU/памяти на 140 днях × 16 часов (до/после), включая холодный `spawn`.
- Проверка технологических границ J по паспорту каждой камеры; расчёт Q при смене загрузки остаётся внешним (физической связи пока нет).
- Оптимизация нескольких **разновременных** коррекций (в текущей фазе только одно время и до 3 действий).
- Калибровка помола, износа и Блейна по реальным пробам, тест сохранения массы и качества на мелкой сетке между контрольными точками.
