# Фаза 15: Windows EXE без репозитория

## Реализовано в коде

- `build_windows.cmd` — двойной клик по команде сборки на компьютере разработчика.
- `scripts/build_windows.ps1` — режимы OneFile и OneDir (и Console для отладки).
- `requirements-build.txt` — зависимости сборки, не требуются пользователям.
- `project/operator_export.py` — выборочный JSON/XLSX через XlsxWriter.
- `main.py` сохраняет `freeze_support` до импорта GUI и не требует Python на ПК получателя.

## Ограничение, не связанное с упаковкой

Текущая реализация последовательных симуляций соединяет модельные траектории
по оси наработки. Для физически точной непрерывности износа между отдельными
запусками потребуется передавать состояние всех изношенных когорт мелющих тел
в следующий расчёт; эту задачу нельзя считать решённой простой склейкой графиков.
Точность качества/Блейна требует заводской калибровки.

## Дополнение 14.11.2026: кодировка сценариев сборки

Windows PowerShell 5.1 по умолчанию может неверно прочитать UTF-8 скрипт без BOM как ANSI. Признаки: строки вида `РћС€...`, синтаксические ошибки `UnexpectedToken` и сообщения об отсутствующих фигурных скобках.

**Решение:** `build_windows.ps1` и `build_windows.cmd` полностью ASCII. Текст ошибок и сообщений в них — английский. Проверка `tests/test_build_script_encoding.py` остаётся локальной.

**Открытая приёмка:** после `git pull` выполнить полноценную Windows-сборку, запустить EXE на другом устройстве и проверить PySide6, Matplotlib, multiprocessing и XLSX.
