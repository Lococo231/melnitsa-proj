# Фаза 08 — оптимизация скорости и формульный аудит

## Реализуемые изменения
1. Кэшировать внутри одного вызова `quality_at` коэффициенты воздействия мелющих тел (нет повторного перерасчёта на каждом осевом шаге).
2. Сохранять `operating cfg` и текущие когорты/потери в момент предполагаемой коррекции; повторно интегрировать только оставшиеся часы.
3. Параллельно оценивать кандидатов через `ProcessPoolExecutor`/`spawn`, максимум 4 процесса и автоматическая последовательная деградация, если старт недоступен.
4. Не переносить UI-объекты Qt в процессы; в главном потоке остаются обновления интерфейса.
5. Добавить проверку равенства результатов с `parallel=False`/`parallel=True` и формульные инварианты.

## Риски и задачи проверки
- Тесты в реальной Windows/PyCharm с Python 3.11 или 3.13, особенно из QThreadPool + ProcessPoolExecutor.
- Проверка при событии догрузки/смены параметра **в точности в час коррекции**.
- Нагрузочные измерения для 20+ дней с 50–100 кандидатами, наблюдениями и несколькими журналами.
- Верификация заводской модельной калибровки и фактических кривых Блейна, R0,08/R0,045, Q(t).
- Не делать коммит или push без прямой команды. GitHub Actions не восстанавливать.
